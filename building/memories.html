Memories

Why

Snapchat caps how many saved memories you get to keep and charges for anything past the line. Ten years of mine are in there, 2016 to now, and I did not have a copy of a single one of them anywhere else.

What

The export does not hand back a photo library. It hands back parts. Every memory comes out split in two, the picture or video in one file and the caption you wrote on it in a separate see-through image, so they arrive as strangers who have to be reintroduced. Most of mine turned out to have no caption at all.

So the work is pairing every caption back to the photo it belongs to, painting it back on, and ending up with something that behaves like a real library instead of a folder holding 2,659 loose pieces.

Log

  • Sep 9

    Started the public version tonight, and the first thing it did was tell me I had been wrong about my own library since August.

    I had written down that the count in the Snapchat app, 2,007, was wrong and dangerously low, and that the number to verify against was 2,047. That was backwards. 2,007 was right the whole time. Snapchat's manifest says 2,063 because it holds one record per saved copy rather than one per memory, and 56 of my memories were saved twice. Take the 16 videos Snapchat never delivered off 2,007 and you get the 1,991 I actually received. Add the 56 second copies and you get the 2,047 files in the download. Every number I had was explainable, and I had picked the wrong one to trust.

    The checking reads 356 KB out of 5.02 GB. A zip keeps its list of contents at the end of the file instead of the start, so every filename, size and timestamp can be read off the last few hundred kilobytes without unzipping a single photo. The real capture time lives in that list too, which matters because Snapchat strips the date out of the photos completely and the dates it writes into the videos are not reliable.

    My duplicate checker was wrong three times before it was right, and Apple Photos is what caught it. First I matched on Snapchat's ID, which found 56. Photos then merged five more on import that I had missed, because those five are the same picture saved under two different IDs. So I matched on the file contents instead, which found 27, and that was too many, because the same photo saved twice with two different captions becomes two genuinely different pictures. Folding the caption in gave 8, which still did not agree with Photos. At that point I stopped reasoning about the zip and hashed all 1,991 finished files directly. 1,972 distinct pictures, 18 duplicate groups, 19 redundant files.

    The useful part is what that means the tool can honestly say. It can prove two entries are identical from the index alone, and those findings were all real, but it cannot catch every case without decoding the pictures, because Snapchat sometimes stores the same photo with different bytes and re-encoding flattens them to the same result. So it reports a floor and says so, rather than a number that sounds exact and is not.

    My library is 1,972 now, it is in Photos, and I checked every date by reading all 1,972 back out and comparing them. Photos converts the world clock to my clock by itself, which I had not expected, so a photo I took at 9pm shows up on the evening I took it instead of the next morning. There is also a calendar file now, one all-day event for each of the 341 days I have memories on, so the memories come back to me without my having to go looking.

  • Aug 27

    The library was built on the 24th, the same night I got my full data download. 2,047 files, every caption painted back on, every date correct inside and out. When I picked it up tonight, I realized I couldn't explain one thing that had happened. Claude had built it and caught every trap, and I said, "Great, let's fix it." This is the exact failure that I know in myself and that I want to prevent, so tonight I made myself understand the three things that are worth understanding.

    1. These videos were stored sideways, because the camera sensor in a phone cannot turn. Portrait videos get saved in landscape with a note that says to rotate it when you play it. Players obey the note, which is why a general user never sees it. My captions in Snapchat were made for the upright version, so they had to be sized to the upright measurements. Using the files' raw landscape measurements instead would have squashed and stretched the caption on 80% of my videos, and no error would have fired, because a mangled caption is still a perfectly valid video.

    2. Snapchat's dates inside my videos were not correct. Their servers reprocess the videos in batches and stamp each one with the date it was reprocessed, not the date I filmed it. Three videos from different days in fall 2017 all claimed the same moment in January 2018, seconds apart. The real dates came from two independent sources that agreed perfectly across all 2,047 files: the timestamp each file carries inside the zip, and Snapchat's own manifest.

    3. A script that finishes with no errors means pretty much nothing. A clean run can and will hand you squashed captions, shortened videos, silent audio, and wrong dates. The only checks that count come from outside, comparing what came out against something the script never touched.

  • Aug 24

    The archives came the same day I asked, three zips, 4.7 GB. I checked what was inside before unzipping anything, which caught a count that would have hidden 16 missing videos. Everything is out. The actual work starts next.
